# GitHub Pages 한국어·초보자 중심 UI 개편 제안서

상태: **제안 / 구현 보류**
작성 목적: 실제 웹 코드를 바로 바꾸지 않고, AI-A/B/C/D/E가 변경 의도와 구조를 먼저 공유·검토한 뒤 순차 구현하기 위함
대상: `juhwan7/korea-market-behavior-lab` GitHub Pages
작성일: 2026-09-29

---

## 1. 사용자 요청

현재 GitHub Pages는 기술적으로는 상태를 많이 보여주지만, 처음 보는 사용자가 다음을 빠르게 구분하기 어렵다.

1. 이미 실제로 구현되고 검증된 기능
2. 아직 개발·검증 중인 기능
3. 지금 시장에서 중요한 내용
4. 시스템이 정상인지 이상이 있는지
5. 영어 상태값이 무엇을 뜻하는지

또한 사용자는 영어를 편하게 읽지 못하므로, 사용자 화면은 **한국어를 기본 언어**로 한다.

이 변경은 바로 구현하지 않는다.

먼저 이 문서를 공용 설계 기준으로 사용하고, 다른 AI들이 변경 의도와 영향 범위를 확인한 뒤 실제 UI 변경을 진행한다.

---

## 2. 가장 중요한 UI 원칙

목표는 "정보가 많은 페이지"가 아니다.

목표는 처음 방문한 사람이 **10초 안에 아래 4가지를 이해하는 페이지**다.

- 이 프로젝트가 무엇을 하는지
- 지금 시장에서 무엇이 중요한지
- 무엇이 실제 구현 완료됐는지
- 무엇이 아직 구현·검증 중인지

사용자는 GitHub 구조, workflow, SHA, JSON schema를 몰라도 된다.

기술 상세는 기본 화면에서 숨기고, 필요한 경우에만 펼쳐서 본다.

---

## 3. 최상단 구조

페이지 최상단은 아래 순서를 기본안으로 한다.

### 3.1 이 페이지는 무엇인가?

처음 보는 사람을 위한 2~3문장 설명을 둔다.

예시:

> KMB는 한국 주식시장의 뉴스, 수급, 거래대금, 상대강도, 시장 이상 움직임을 여러 AI가 함께 분석하고 검증하는 연구 시스템입니다.
> 확인된 사실과 아직 검증 중인 가설을 구분하며, 시스템 상태와 개발 진행 상황도 함께 공개합니다.

전문용어 설명은 처음 1회만 괄호로 보조한다.

### 3.2 지금 시장 한눈에

가장 먼저 보여줄 정보:

- 코스피
- 코스닥
- 거래대금
- 시장 강약
- 주요 테마
- 대장주 변화
- 중요한 뉴스/공시
- 확인된 시장 변화
- 검증 중 가설

데이터가 없으면 숫자를 만들지 않고:

- 확인 불가
- 아직 수집 안 됨
- 최근 정상 데이터

처럼 한국어로 표시한다.

### 3.3 시스템 한눈에

복잡한 Health Matrix보다 먼저 아주 단순한 요약을 보여준다.

예시:

- 전체 상태: 일부 확인 필요
- 정상 AI: 2 / 5
- 확인 필요 AI: 3 / 5
- 현재 복구 중: 0
- 자동 배포: 정상
- 마지막 업데이트: 3분 전

세부 기술표는 그 아래에서 펼쳐서 본다.

## 4. "구현 완료"와 "구현 중"을 반드시 분리한다

이번 개편의 핵심이다.

한 화면에 완료 기능과 아직 개발 중인 기능을 섞지 않는다.

### 4.1 구현 완료

사용자에게 "구현 완료"로 보여주려면 최소 아래 증거가 있어야 한다.

- 실제 코드/데이터 반영
- 테스트 성공
- 관련 GitHub Actions 성공
- 필요한 경우 실제 Pages 반영 확인
- 기대 상태 확인

예시 카드:

**GitHub Pages 자동 동기화**
상태: 구현 완료
설명: 중요한 데이터가 변경되면 웹페이지를 자동으로 다시 생성하고 배포합니다.
검증: 자동 배포 및 실제 공개 페이지 반영 확인
마지막 확인: 11:05

**5-AI 검토 구조**
상태: 일부 구현 완료
설명: 중요한 변경은 AI-A/B/C/D/E가 각자 다른 관점에서 검토합니다.
주의: 일부 기존 검토 항목은 아직 전체 AI 검토가 끝나지 않았습니다.

완료 여부가 애매하면 "완료"라고 표시하지 않는다.

### 4.2 구현 중

다음 상태는 구현 중 영역으로 보낸다.

- IN_PROGRESS
- REVIEWING
- PENDING
- SHADOW
- RECOVERING
- VERIFICATION_PENDING
- 실험 중
- 데이터 연결 대기

각 항목은 최소 다음을 보여준다.

- 무엇을 만들고 있는지
- 왜 필요한지
- 현재 어디까지 됐는지
- 무엇이 남았는지
- 담당 AI
- 마지막 진행 시각

예시:

**실제 AI 실행 상태 연결**
상태: 구현 중
현재: 저장소의 ACTIVE 문자열과 실제 heartbeat/output을 비교하는 기능은 있음
남은 작업: AI별 실제 workflow/automation 실행 증거 자동 연결
담당: AI-D
다음 단계: service telemetry 연결

## 5. 초보자용 상태 문구

영문 상태값을 그대로 사용자에게 노출하지 않는 것을 기본으로 한다.

내부 데이터에는 기존 enum을 유지할 수 있지만, 화면에서는 아래처럼 한국어 라벨을 사용한다.

| 내부 상태 | 사용자 표시 |
|---|---|
| LIVE | 최신 |
| ACTIVE | 정상 동작 |
| FRESH | 최신 상태 |
| SUCCESS | 성공 |
| RESOLVED | 해결됨 |
| RECOVERED | 복구 완료 |
| DEGRADED | 일부 이상 |
| RECOVERING | 복구 중 |
| STATE MISMATCH | 상태 불일치 |
| STALE | 업데이트 지연 |
| PENDING | 검토 대기 |
| REVIEWING | 검토 중 |
| PASS | 통과 |
| PASS_WITH_NOTES | 통과 · 확인사항 있음 |
| FIX_REQUIRED | 수정 필요 |
| BLOCKED | 진행 차단 |
| UNKNOWN | 확인 불가 |
| MISSING | 데이터 없음 |
| NOT COLLECTED | 아직 수집 안 됨 |
| UNMAPPED | 연결 정보 없음 |
| SHADOW | 실험 중 |

기술 상태명을 꼭 보여줘야 한다면 한국어 뒤에 작게 1회 표시한다.

예:

`일부 이상 (DEGRADED)`

반대로:

`DEGRADED`

만 크게 보여주지 않는다.

## 6. AI 5개 상태 표시 방식

현재 표는 처음 보는 사람에게 어렵다.

기본 화면에서는 각 AI를 한 줄 카드로 단순화한다.

예:

**AI-A · 시장 탐색**
현재 상태: 정상 동작
하는 일: 시장 이상 움직임, 뉴스, 테마, 상대강도 탐색
최근 작업: 코스피 장초반 변화 검토
마지막 활동: 4분 전

**AI-D · 시스템 복구**
현재 상태: 일부 확인 필요
하는 일: 자동화, 데이터 최신성, Pages, 장애 복구
현재 작업: 실제 서비스 상태 연결
마지막 활동: 2분 전

상세 버튼을 누르면 아래 기술 정보를 보여준다.

- 실행 상태
- 생존 신호
- 최근 결과
- 자동 작업
- 대기 작업
- 복구 상태
- 마지막 정상 실행
- 다음 예상 실행

## 8. "오늘 중요한 변화" 영역

단순 최신 로그 목록이 아니라 사용자가 읽을 수 있는 요약으로 만든다.

예:

**오늘 바뀐 것**

- GitHub Pages가 데이터 변경을 자동 감지해 다시 배포하도록 개선됨
- AI-A가 Pages 변경을 독립 검토함
- 시장 데이터 일부는 아직 공식 canonical 입력이 없어 확인 불가 상태
- AI 실행 상태 연결 기능은 개발 중

각 항목에 필요하면:

`왜 중요한가?`

버튼을 두고 펼쳐서 설명한다.

## 9. 구현 완료 판정 로직 제안

웹 생성기는 task/review/recovery/experiment 상태를 읽어 사용자용 상태를 별도로 계산한다.

### 완료 후보

다음과 같이 분류할 수 있다.

- task status = COMPLETED
- recovery status = RESOLVED / RECOVERED
- review item = CLOSED 또는 모든 필수 review 통과
- production 기능 + 외부 검증 증거 존재

### 구현 중 후보

- task = IN_PROGRESS
- review = REVIEWING
- review 중 PENDING 존재
- recovery = RECOVERING
- experiment = SHADOW
- 필요한 evidence 미충족

단순 commit 존재만으로 구현 완료로 분류하지 않는다.

## 10. 한국어 우선 규칙

사용자 화면은 한국어를 기본으로 한다.

### 유지 가능한 영어

다음은 고유명사 또는 식별자이므로 유지 가능하다.

- AI-A / AI-B / AI-C / AI-D / AI-E
- KOSPI / KOSDAQ
- GitHub
- SHA
- KMB

단, 설명은 반드시 한국어를 붙인다.

예:

`AI-B · 증거 검증`

### 사용자 화면에서 한국어로 바꿀 표현

- Health Matrix → AI 상태표
- Recovery → 복구
- Research → 리서치 또는 연구
- Experiments → 실험
- Workflow → 자동 작업
- Queue → 대기 작업
- Last result → 최근 결과
- Last execution → 마지막 실행
- Source Commit → 기준 커밋
- Generated At → 생성 시각
- Material Event → 중요 변경
- Evidence → 검증 근거

## 12. 색상만으로 상태를 구분하지 않는다

색맹, 모바일, 밝기 환경을 고려해 반드시 텍스트 상태를 같이 표시한다.

- 정상: 초록 + "정상"
- 주의: 노랑 + "확인 필요"
- 문제: 빨강 + "문제"
- 개발 중: 파랑/회색 + "구현 중"

색상은 보조 수단이다.

---

## 13. 모바일

모바일에서는 표를 그대로 축소하지 않는다.

AI 상태는 카드형으로 전환한다.

상단에는 최소 다음만 남긴다.

- 시장 핵심
- 시스템 상태
- 구현 완료 / 구현 중
- 현재 장애

긴 리서치, Actions, SHA, 내부 검증 기록은 접는다.

## 14. 구현 순서

실제 코드 변경은 한 번에 전부 하지 않는다.

### 1단계 — 데이터 분류 계층
- implemented
- in_progress
- attention_required
- unavailable

사용자용 상태 계산 함수를 먼저 만든다.

### 2단계 — 한국어 표시 계층
기존 내부 enum은 유지하고 화면 표시 문자열만 한국어로 변환한다.

### 3단계 — 정보 구조 개편
상단을 초보자 중심으로 재배치한다.

### 4단계 — 구현 완료 / 구현 중 분리
완료와 진행중 카드를 별도 섹션으로 만든다.

### 5단계 — 세부 기술 정보 접기
Actions, SHA, raw evidence를 기본 화면에서 숨긴다.

### 6단계 — 모바일
표를 카드로 전환하고 핵심 순서를 고정한다.

### 7단계 — 검증
- unit test
- generator smoke
- desktop 기본 레이아웃
- mobile 기본 레이아웃
- Pages deploy
- 실제 URL
- source commit / timestamp
- 5-AI review

## 15. AI별 검토 요청

### AI-A
시장 정보의 우선순위가 실제 매매/시장 이해 흐름에 맞는지 검토한다.

### AI-B
"구현 완료"라는 표현이 증거보다 과장되지 않는지 검토한다.
상태 문구가 사실보다 확정적으로 보이지 않는지 확인한다.

### AI-C
확률·실험·SHADOW 결과가 완료 기능처럼 오해되지 않는지 검토한다.

### AI-D
상태 계산, freshness, recovery, Pages 배포와 충돌하지 않는지 검토한다.

### AI-E
전체 정보구조, 초보자 이해도, 모바일, Progressive Disclosure 관점에서 개편안을 검토한다.

## 16. 구현 금지 조건

이 문서가 생겼다는 이유만으로 바로 UI를 전면 변경하지 않는다.

다음 순서를 지킨다.

`제안 기록 → 다른 AI 인지 → 검토/보완 → 구현 task 승격 → 단계별 코드 수정 → 테스트 → Pages 검증`

특히 다른 AI가 현재 Pages 관련 작업을 진행 중이면 동일 파일을 동시에 수정하지 않는다.

## 17. 기대 결과

개편 후 사용자는 첫 화면만 보고 다음처럼 이해할 수 있어야 한다.

> "이 프로젝트는 시장과 AI 시스템을 같이 분석하는구나."

> "이 부분은 이미 실제로 작동하는 기능이구나."

> "이 기능은 아직 만들고 있구나."

> "지금 시스템에 문제가 있는지 바로 알 수 있구나."

> "영어 기술 용어를 몰라도 대략 이해할 수 있구나."

이 이해가 가능해야 이번 UI 개편을 성공으로 본다.
